2. **区级目的地没有直达铁路**：新增 `TRANSPORT_CITY_ALIASES` / `resolveTransportCity()`，顺德 → 佛山；`planTransport` 用枢纽城市查询但保留原始地名展示，并渲染 `hub_note`。

### 重要的操作性结论（下次直接复用）

- 抓取过的目的地**不必重新抓取**：`03_fetched_posts.json` + `08_validation_report.json` 存在时，编排器自动走 `regenerateFromSavedDetails`，只重新抽取，几秒完成。改抽取逻辑后应先跑这个再跑全流程。
- 单个目的地的一轮完整实时流程约 **13 分钟**（25 篇详情 ≈ 5 分钟；图片定向补搜最慢）。
- **携程 `hotel-search` 容易被限流**：连续探测后会持续返回 `Navigation rejected`，需要用户在本机 Chrome 完成验证码/滑块才能恢复。不要反复重试。
- **携程 `train` 对没有直达车次的区县会返回「卡片已渲染但找不到车次锚点」**，这不是错误而是「无直达」，需要按枢纽城市归一。
- **`opencli ctrip hotel-search` 只接受城市 ID**，且 `district` 字段实际是地标描述（如「近佛山西站 · 招大党建主题公园」），不是行政区，不能用它做区域过滤。
- 佛山（cityId 251）首屏候选**不含大良酒店**，最近的在北滘（距清晖园约 11.6 km）。如需住在清晖园步行范围，得在携程按「大良」直接搜。
- zsh 里 `set -- $var` **不会分词**，写探测循环要用 `${var%%:*}` / `${var##*:}`。
- `grep -c` 在这类单行 HTML 上统计的是行数，要用 `grep -o ... | wc -l` 统计出现次数。

- 最终产出 `output/顺德-2026-10-02-2026-10-07.html`：valid/complete 均为 true，7 景点、10 美食、9 条提醒、39 个来源，3 个交通区块（去程 / 返程 / 次日返程）。

### 本轮新增能力（可复用）

1. **`--outbound-period` / `--return-period` 真正生效**：`planner.js` 的 `score()` 用它们做排序惩罚（morning = 出发时间须落在 07:00–11:59；late_night = 抵达时间须 ≥21:00）。
2. **双返程窗口**：用户常给“当天深夜**或**次日清晨”这种二选一。`planTransport` 现在会额外查询 `end_date + 1` 的返程（`return_next_day`，按清晨偏好排序），`report.js` 渲染成独立分块“返程备选（次日清晨）”。`queryPair` 增加了第 6 个参数 `preferences` 覆盖项来实现这一点。
3. **`scripts/render-plan.js`（新增，仅重渲染）**：`node scripts/render-plan.js <plan.json> [out.html]`，读 `data/processed/travel-plans/*.json` 直接出 HTML。**纯展示层改动绝不要重跑全流程**（11 分钟），改完 report.js 用它秒级重出。
4. **跨夜航班展示修正**：携程跨夜卡片只给 `+N天`，适配层归一成 `duration="24小时"`；个别卡片还会把到达时间渲染成与起飞相同的占位值，导致出现“23:55 → 23:55”。`report.js` 新增 `isOvernight()/arrivalLabel()`，改成“23:55 → 次日抵达”“… · 跨夜航班”。

### 产物命名：`--label` 前缀（防止覆盖 output/ 示例）

**教训**：`generateTravelPlan` 的文件名只由「目的地 + 起止日期」决定，所以同一路线换个出发地、或同一条路线再跑一次，都会**直接覆盖** `output/` 里上一版 HTML（而 `output/` 是提交进仓库的示例目录）。本轮就撞上了：`丽江-香格里拉-2026-10-02-2026-10-07.html` 被我这一轮覆盖。

**已修**：`orchestrator.js` 新增导出 `planSlug(plan, label)`，`generateTravelPlan` 支持 `input.label` / `options.label`；CLI 增加 `--label=`。`--label=上海` → `上海-丽江-香格里拉-2026-10-02-2026-10-07.html`。

**注意一个容易搞错的事实**：被覆盖的那版 `丽江-香格里拉-2026-10-02-2026-10-07.html`（HEAD 中 446877 字节）**并不是**“丽江出发/北京出发”的版本，它也是**上海 → 丽江 · 香格里拉**（生成于 07:17:52Z），只是没有 `report.js` 的时间偏好说明和次日返程分块。**不要凭文件名推断出发地**，要看 hero 里的 `<p>`。

恢复做法（工作区当前内容先另存，再从 HEAD 取回）：
```bash
cp "$P" "$NEW" && cmp "$P" "$NEW"     # 先确认字节一致
git checkout -- "$P"                   # 再用 HEAD 版本覆盖回来
```
`output/` 是 git 跟踪目录，覆盖前先 `git status --porcelain output/` 确认目标文件是否 tracked（tracked 才有救）。
